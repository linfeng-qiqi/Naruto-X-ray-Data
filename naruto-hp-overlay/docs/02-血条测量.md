# 血条测量

血条位置**不能写死坐标**，否则换分辨率、换异形屏、改模拟器尺寸全都会错位。这里的方案是每帧从截图像素里反推。

## 为什么不能写死

最早的实现把测量窗口固定成 `y ∈ [0.106H, 0.124H]`，实际血条在 `y ∈ [0.077H, 0.088H]`，于是：

- 量到的是血条上方的空白，读数恒为 0；
- 叠加层画在 `y = 0.16057`，和真实血条差了大半个屏幕高度。

## 测量步骤

### 1. 找行带 `FindBarBand`

遍历画面右侧区域每一行，统计「橙色像素」数量：

```
R > 90  且  R > 1.5·G  且  R > 1.4·B
```

橙色像素数量超过阈值的连续行，就是血条的上下边界。这样量出来的是**真实条高**，与分辨率无关。

### 2. 取最长连续橙段

左右端点法会被左边的角色头像金边污染 —— 金边也是橙色，于是血条左端被算到头像上，宽度直接翻倍。

改成：**每一行只取最长的连续橙段**，那就是血条本体。

### 3. 折算比例

```
满血宽度 = 0.1765 × 屏宽      (339 / 1920，实测满血正好量成 100%)
血量比例 = 橙段宽度 / 满血宽度
```

所有行的比例取 **70 分位**，避开描边和抗锯齿造成的干扰行。

### 4. 写回配置

量出来的矩形通过 `ApplyBarRect` 写回 `overlay.ini[view]`，叠加层绘制和测量使用同一份坐标，不会出现「量得准但画得偏」。

## 归属判定

内存读到的两个血量必须对上是「我方」还是「敌方」。判据用屏幕实测值交叉验证：

```
每 3 秒：
  比较 内存读数A 与 屏幕测量值(我方条)
  比较 内存读数B 与 屏幕测量值(敌方条)
  如果 A 更接近敌方条 且 B 更接近我方条 → SwapSides()
```

- 认反了就交换，并把结果写回缓存；
- 连续两次都对不上，说明缓存过期了 → 丢掉缓存重新全量扫描。

这套机制是必要的：同一个战斗场景里，我方和敌方的血块在内存里长得一模一样，只有 owner 和间距能区分，而间距每个账号都不同。

## 参数

| 参数 | 值 | 含义 |
|---|---|---|
| `BAR_SLOT_FRAC` | `0.1765` | 满血宽度占屏宽比例（339/1920） |
| 取用分位 | `70%` | 所有行的血量比例取 70 分位 |
| 橙色阈值 | `R>90, R>1.5G, R>1.4B` | 血条颜色判定 |
| 校验周期 | `3 s` | 交叉校验间隔 |
