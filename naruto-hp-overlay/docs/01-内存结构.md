# 内存结构

本文记录实测确认的结构。地址是某一局的运行时地址，**每次重启都会变**，只有偏移和间距是稳定的。

## 1. 血量块

双方血量各存在「两份值」里，两份结构完全一致。

```
偏移      类型      内容
+0x00     float     当前血量比例（满血 1.0，空血 0.0）
+0x04     byte[8]   全 0
+0x0C     int32     固定值 1
+0x10     uint64    owner 指针（指向 UI 组件）
+0x18     byte[32]  未使用的填充
+0x38     byte[24]  TAIL 特征（见下）
```

TAIL 的 24 字节：

```
01 00 00 00   01 00 00 00   02 00 00 00
01 00 00 00   01 00 00 00   01 00 00 00
```

扫描流程：先在整个可读堆里找 TAIL，命中后回退 `0x38` 校验头部（`hp ∈ [0,1]`、`+04..+0B` 全零、`+0C == 1`、owner 是合法堆指针），再按 owner 配对。

> 血量 0 是合法状态（被击败）——只要形状和 owner 校验通过就必须接受，不能因为「值是 0」就丢掉。

## 2. 两份值的间距

同一实体的两份血块 owner 相同，间距固定但**每个账号可能不一样**，所以不能写死：

| 实体 | 本账号实测间距 |
|---|---|
| 我方 | `0x46C0` |
| 敌方 | `0x36C0` |

配对时用 `0x100 ~ 0x8000` 作为合法间距范围扫描。

## 3. owner 与残块过滤

同一实体两份血块的 owner 相同；不同实体也可能共享同一个战斗 owner。

上一局遗留的血块没人清理，owner 各不相同 —— 所以规则是：**owner 在整个命中集合里出现次数 ≥ 2 才保留**。

## 4. 属性记录数组

血量值属于一个步长 `0x240` 的属性记录数组：

```
记录基址     72E53BB25240, 72E53BB25480, 72E53BB256C0, ...
hp 偏移      +0x178
```

这条记录是「属性快照」，不是活对象：14 秒内只有 `+0x078` 一个字段有微小变化，其余全静止。里面还有约 19 根指针，两跳展开 60 个对象后 20 秒内只有 3 个字段在动（其中一个是全局时间的副本）。

**技能冷却不在这棵树里。**

## 5. 全局时间源

引擎用时间戳体系，实测有 4 个独立的 float 秒计时器，每帧递增：

```
72E5C0FC64F8    7825.425 → 7855.513   (经过 29.85s，总增 30.088)
72E5C11506C8    7194.934 → 7225.032   (总增 30.098)
72E5C11506D8    7194.916 → 7225.028   (总增 30.112)
72E4EA6B96B4    8280.608 → 8300.325
```

这印证了 `结束时间 = 全局时间 + CD` 的模型，但顺着这个体系没能找到 CD 字段本身。

## 6. Il2CppClass

见 [03-il2cpp-运行时内省.md](03-il2cpp-运行时内省.md)。要点：

```
Il2CppClass:
  +0x10   const char*  name
  +0x18   const char*  namespaze
  +0x80   FieldInfo*   fields

FieldInfo（步长 0x20）:
  +0x00   const char*     name
  +0x08   Il2CppType*     type
  +0x10   Il2CppClass*    parent
  +0x18   int32           offset
```

用 `System.String` 验证：字段表里 `_stringLength` 的 offset 是 `0x10`、`_firstChar` 是 `0x14`，与 C# string 对象的真实布局一致。

## 7. 地址漂移

换号 / 重启 / 换地图都会触发堆重分配，上一局的绝对地址失效（表现为整片内存变成 0，或读到图形缓冲区的垃圾）。

所以缓存里存的必须是**静态链**：

```
绝对地址 = *(*(*(模块基址 + root) + off0) + off1) ... + off(n-1)
```

`libil2cpp.so` 的基址每次启动都不同，但**模块内偏移 `root` 和各级 `off` 在同一个游戏版本里是稳定的**。
